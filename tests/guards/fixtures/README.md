# Guard fixtures (test group T1.3)

One bad file and one good file per anti-pattern guard. `anti-pattern-guards.test.js`
copies each fixture into a throwaway directory outside the repo, at the path the guard
actually watches (for example `ap1/bad-reads-env.js` becomes `src/agent/env-reader.js`),
runs the guard there, and deletes the directory afterwards. Nothing is planted in the
repo tree, so a test run leaves no stray state (lesson L-P02).

This folder is in `eslint.config.mjs`'s global `ignores`. Without that, the normal
`npm run lint` would fail on the planted violations.

instead of committed: 600 padding lines and a deliberate duplicate basename would be
noise in the tree, and the AP7/AP9 scripts scan the repo, so they would flag themselves.
