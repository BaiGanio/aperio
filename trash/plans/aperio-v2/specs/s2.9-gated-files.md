## 1. v1 study (read at `archive/v1-final`)

**How v1 did it:**
- `lib/routes/paths.js` (276 lines) → `realpathSafe()` resolves symlinks on the longest existing
  prefix (sync); `isUnder(path, roots)` = realpath + `startsWith(root + sep)`.
  `isReadPathAllowed` / `isWritePathAllowed` read one allowlist (DB-persisted, seeded from
  `APERIO_ALLOWED_PATHS`, a hard floor of `cwd` + `var/scratch` always added) or a per-session
  override from `AsyncLocalStorage`. `resolveScratchPath()` rewrites model paths into a session scratch dir.
- `mcp/tools/files/{read,write,perform,delete,interrupt,generate}.js` → 9 model tools
  (`read_file`, `scan_project`, `grep_files`, `read_docx`, `write_file`, `append_file`, `edit_file`,
  `delete_file`, generators). Each handler: `isXPathAllowed(p)` → `existsSync` → `statSync` → `readFile(p)`.
- `helpers.js` → `isSecretFile()` deny-list (`.env*`, keys, `.pem` …), extension allowlist,
  500 KB cap, `formatPathError()` that tells the model the right path.

**Best parts (keep):**
- One containment function, shared by everyone. Boundary is `root + sep`, so `/allowed-evil` is not
  inside `/allowed` (v1 test). Win32 separator handled by `path.sep`.
- Symlinks resolved before the compare (v1 test: link inside → file outside is denied).
- `~` and `~/x` expand; `~bob/x` does not (PATH-01).
- Secret-file deny-list, checked before anything else. 500 KB read cap.
- A denied path tells the model which folders are allowed (small models retry well with a hint).

**Bad parts (drop / fix):**
- **Check-then-use (AP3, L-C21).** The check runs on a path string; the open runs later on the same
  string. A symlink swapped in between wins. Every v1 handler has this gap.
- **Sync fs on the request path (AP4):** `realpathSync`, `existsSync`, `statSync`, `readFileSync`.
- `write.js` expands `~` to **`process.cwd()`**, `paths.js` expands it to **home**. Two meanings.
- The hard floor always allowed `cwd`: the model could write Aperio's own source.
- Module-level consts read env at import (`SEED_ENV`, `BASE_DIR`) — TR15.
- Many moving parts: DB allowlist, session override, scratch redirect, one-level folder heuristic,
  confirm tokens. None is needed for the gate.
- `readFileHandler` opens a FIFO with no guard → the read can block forever.

**Lessons that apply:** L-C21 (TOCTOU, swap test) · L-C03 (enforce at use, not at declaration) ·
L-C20 + issue #528 (Windows ARM paths; #528's simulator wrote 299 backslash files into the repo root
— never run a win32 simulation against the real fs) · L-M16 (eval runs isolate allowed paths) ·
TR15 (config through a function) · AP3, AP4, AP5, AP6.

## 2. Spec (the contract)

**Goal:** one place that reads and writes a file **only** if the file it really touched is inside an allowed folder.

**Behaviour — read (`gatedRead`):**
1. Reject at once: non-string, empty, or contains `\0` → `E_BAD_PATH`. No fs call happens.
2. Expand `~` / `~/…` to home (one function, both read and write). A relative path joins to the
   **first** allowed folder. `\\?\` and `\\.\` device prefixes → `E_BAD_PATH`.
3. Allowed folders = `config.APERIO_ALLOWED_PATHS` (comma list) from the `config` the caller passes **per call**, each one `realpath`ed
   per call. Empty list → `E_NO_ALLOWED_DIRS` (fail closed). A folder that does not exist is skipped and logged.
4. **Fast deny:** `realpath(path)` not inside → `E_NOT_ALLOWED`, no open (so we never open an outside
   file or device). This is not the gate; step 5 is. **Then open** (`O_RDONLY | O_NONBLOCK`, so a FIFO cannot hang us). Then `fstat` the handle
   (`bigint: true`, so Windows file ids do not lose precision). Not a regular file → `E_NOT_FILE`.
5. **Then prove the handle is inside:** `realpath(path)` must be inside an allowed folder, **and**
   `stat(realpath)` must have the same `dev` + `ino` as the handle. A mismatch means the path changed
   under us → `E_SWAPPED`. Bytes are read **only from the handle**, so a swap after this point changes nothing.
6. Secret deny-list on the basename of the **requested** path **and** of the **real** path
   (a `notes.txt` link to `.env` is denied) → `E_SECRET`.
7. Size: `fstat` size > cap → `E_TOO_LARGE`. Read at most cap + 1 bytes anyway. Decode UTF-8.
8. The handle closes on every path, success or error (`finally`).

**Behaviour — write (`gatedWrite`):** the same 1–3 and 6, then:
- `mode: 'create'` — parent folder must exist (no `mkdir -p`). `realpath(parent)` must be inside;
  open `realParent/name` with `O_CREAT | O_EXCL | O_NOFOLLOW | O_WRONLY`. Exists → `E_EXISTS`.
- `mode: 'overwrite'` — open the existing file `O_WRONLY` (**no** `O_TRUNC`), then the same
  step-5 proof. Only **after** the proof: `ftruncate(0)` + write through the handle.
- Content over the write cap → `E_TOO_LARGE` before any fs call.

**Interface** (`src/files/paths.js`, async only, no module state):
```js
gatedRead(path, { config, log })              → { ok: true, text, realPath, bytes } | GateError
gatedWrite(path, text, { mode, config, log }) → { ok: true, realPath, bytes, created } | GateError
isInside(realPath, realRoot, pathImpl = path) → boolean   // pure; tested with path.win32 too
expandTilde(p) → string                                    // ported v1, pure
// test seam: { hooks: { beforeOpen(), afterOpen(fileHandle) } } — tests only, used by the swap test
// GateError = { ok: false, code, message }   — never thrown (AP5)
```

**Errors** (each one also logged at `warn` with code + requested path, never content):
`E_BAD_PATH` · `E_BAD_ARGS` (write: bad `mode` or non-text content) · `E_NO_ALLOWED_DIRS` · `E_NOT_ALLOWED` (message lists the allowed folders, like v1) ·
`E_NOT_FOUND` · `E_NOT_FILE` · `E_SECRET` · `E_TOO_LARGE` · `E_EXISTS` · `E_SWAPPED` · `E_IO` (with `err.code`).

**Limits:** new config keys `FILE_READ_MAX_BYTES` (default 512000, v1's 500 KB) and
`FILE_WRITE_MAX_BYTES` (default 512000). No cache of any kind (AP6). No sync fs (AP4).

**Known limits (written down, not fixed):** a **hard link** inside an allowed folder to an outside file
passes (same inode; making one needs write access inside). In `create` mode, a parent folder swapped
for a symlink in the gap can leave an **empty** file outside; the content is never written there.
Node has no `openat` / `O_RESOLVE_BENEATH`, so this is the best one-step gate plain Node gives.

**Non-goals:** no model tool (§4.1 = A; the tool array stays at 5) · no append / edit / delete / list-folder / grep ·
no DOCX / PDF · no session scratch dir or path rewriting · no UI allowlist or DB setting · no confirm
dialog · no `mkdir -p` · no extension allowlist (the secret list + UTF-8 text is the rule).

**Keeps from v1:** `root + sep` boundary; realpath before compare; `~` rules; secret deny-list; 500 KB
cap; error lists allowed folders. **Drops:** check-then-use, sync fs, the `cwd` floor, `~`→cwd,
DB allowlist, session override, scratch redirect, 9 tools.

## 3. Acceptance (becomes T2.9)

All fs tests run in a `mkdtemp` sandbox under the OS temp dir; nothing is written in the repo tree.
- [ ] **deny** `allowed/../outside/secret.txt` (`..` escape) → `E_NOT_ALLOWED`; no byte read.
- [ ] **deny** symlink `allowed/link.txt` → `outside/secret.txt` → `E_NOT_ALLOWED` (ported v1).
- [ ] **deny** symlinked parent folder `allowed/dir` → `outside/` (read and create).
- [ ] **deny** absolute path outside (`outside/secret.txt`, `/etc/hosts`) → `E_NOT_ALLOWED`.
- [ ] **deny swap:** a test hook between open and proof swaps `allowed/f.txt` for a link to outside →
      `E_SWAPPED`; read returns no outside bytes; overwrite leaves the outside file unchanged byte for byte.
- [ ] **deny** null byte (`allowed/a.txt\0.png`) → `E_BAD_PATH`, and no fs call (spy).
- [ ] **allow** a normal file inside → `ok`, exact text; create + overwrite inside → file on disk is exact.
- [ ] ported v1: sibling prefix `allowed-evil`, root itself, `~` / `~/x` / `~bob/x`, `sep` boundary.
- [ ] secret: `.env`, `.env.example`, `id_rsa`, `x.pem`, and `notes.txt` → `.env` link → `E_SECRET`.
- [ ] limits: file of cap + 1 → `E_TOO_LARGE`; FIFO → `E_NOT_FILE` and returns (no hang); folder → `E_NOT_FILE`.
- [ ] config: empty `APERIO_ALLOWED_PATHS` → `E_NO_ALLOWED_DIRS`; change the value between two calls
      → the second call uses the new value (no frozen const, TR15).
- [ ] create: existing file → `E_EXISTS`; missing parent → `E_NOT_FOUND`, no folder made.
- [ ] handle hygiene: the handle seen by `afterOpen` is closed (`fd === -1`) after ok, `E_TOO_LARGE` and `E_SWAPPED`.
- [ ] **#528, pure, no fs:** `isInside` with `path.win32`: `C:\a\b` in `C:\a`; `c:\a\b` vs `C:\a`
      (drive case); `C:\a-evil`; `D:\a\b`; `C:/a/b` (mixed separators); `\\server\share\x`; `C:\a\..\b`.
- [ ] guards: `src/files/paths.js` has no `*Sync` call (AP4 lint covers it); a planted
      `import fs` in `src/tools/` still fails AP3 lint.

## 4. Decisions (were open questions; developer 2026-11-12)

1. **No model file tool in v2 core: A.** S2.9 builds and tests the gate only. The tool array stays at
   5, so the KV prefix and the S2.7 rev 4 numbers do not change. A later step (S3 file drop, or a
   `read_file` tool through the return gate) calls the gate and brings its own eval number.
   Feature Ledger "Ported in" for `files.js` will say "gate only (S2.9); tool deferred".
2. **`working-with-files` skill: S2.10.** It is cut there, and only if a file tool exists by then.
