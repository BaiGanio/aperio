## 1. v1 study (read at `archive/v1-final`)

**How v1 did it:**
- `lib/agent/providers/llamacpp.js` (807 ln) → `runLlamaCppLoop()` — trims history, builds system prompt + tools, preflights the size, sends `POST /v1/chat/completions` (stream), and runs the whole tool loop: retries, leak recovery, repeat breaker, step cap, VLM bridge.
- `lib/streaming/llamacppHandler.js` (307 ln) → `LlamaCppStreamHandler` — SSE reader: split-line buffer, idle timeout, thinking timeout, `data: {"error"}` capture, tool-call delta merge, `timings`.
- `lib/tools/executor.js` (773 ln) → `parseArgs()`, `extractAngleToolCall()` (Ornith), `extractPipeAngleToolCall()` (gemma), `detectToolCallLeak()`, `recoverToolName()`.
- `lib/helpers/startLlamaCpp.js` (581 ln) + `lib/helpers/llamacpp/*` (6 files) + `ggufModelFacts.js` (216 ln) — router mode, a `models.ini` preset (main + VLM + wiki model), RAM-fit context sizing, PID / `state.json` adoption, detached process.

**Best parts (keep):** the SSE reader (split lines, idle and thinking timeouts, streamed errors) · the shape-keyed leak parsers (not name-keyed) · empty-completion retry with thinking off · `parallel = 1` · the GGUF header reader · log file unlinked before create (v1 NUL-hole bug).

**Bad parts (drop / fix):**
- Retry nudges and loop guidance are **appended to the system prompt** (`appendNudges`, ln 511) → the prefix changes on every retry. `fitToolsToContext()` **pops tools** when over budget → the tool prefix changes. Both break A2 / L-M04.
- `parseArgs()` regex-"repairs" bad JSON for non-destructive tools (can shift string bounds). `extractTextToolCall()` turns bad JSON into `{}` (ln 316). → Test Reuse Map edge case.
- `provider.name === "llamacpp" / "gemini" / "deepseek"` label `if`s (AP2). `process.env` read at module level, 6+ keys (AP1). Router, VLM bridge, wiki model, perf profiles, PID adoption: not core.
- The header KV math is wrong (see numbers). v1 never set a thread count (llama.cpp took 8 of 10 cores).

**Lessons:** L-M03/L-M04 (stable prefix) · L-M05 (two leak shapes) · L-M06 (Ornith repeat loop) · L-M07 (gemma empty completion; inline `<think>`) · L-M08 (server must get the real context) · L-M09 (do not trust header KV) · L-M15/L-M18 (fixed 5 tools; re-sending schemas is fine).

## 2. Spec (the contract)

**Goal:** stream one model call to a llama-server we start, with tool calls parsed honestly and a prefix that never changes by our hand.

**Behaviour — adapter (`src/providers/`: `sse-stream.js`, `tool-calls.js`, `chat-provider.js`):**
1. `streamChat({ messages, tools, signal, thinking })` sends one streamed request. `tools` is the fixed array, serialized **once per session** and reused as the same string.
2. The adapter never edits the system message or the tool array. Retry nudges go in a **trailing message after history**. Over budget is the budget function's job, never the adapter's.
3. Stream reader: port of v1 SSE handler (split lines, idle + thinking timeouts, streamed `error`, `timings`, usage).
4. Tool args: empty → `{}`. Bad JSON → **no repair, no `{}`**: the call becomes `{ name, error: "bad_tool_json", raw, message }`, an event `tool_args_invalid` is sent, and the loop returns the error to the model as the tool result.
5. Leak parsers run by **output shape**, on every model: angle-bracket (Ornith), pipe-delimited (gemma), corrupt-name recovery. A leak that does not parse, or a system-prompt echo → `retract` + one retry, then an honest error.
6. Empty completion → one retry with `enable_thinking: false`, then the fallback text.
7. Capabilities, not names (AP2): `{ tools, thinking }` come from the GGUF chat template. No `provider.name` in any branch.
8. Every request records `prefixHash = sha1(toolsJson + systemText)` for the eval (A1 item 4).

**Behaviour — launcher (`src/providers/`: `gguf-header.js`, `gguf-cache.js`, `llama-launcher.js`). All async — `src/providers/` is not boot code (AP4).**
1. Find the GGUF in the HF cache from `LLAMACPP_MODEL`. `LLAMA_CACHE` empty = `~/.cache/huggingface/hub`. Missing → error naming `npm run model:fetch` (the script also fetches the llama model). No download at boot.
2. Read the header: `context_length`, arch, chat template. `ctx = min(LLAMACPP_SERVE_CTX, context_length)`. **No RAM-fit KV math** (measured 10× off).
3. Spawn, not detached, owned by the app: `-m <gguf> --jinja --parallel 1 -c <ctx> -t <T> -tb <T> --host 127.0.0.1 --port <port>`. Log to `var/logs/llama-server.log` (unlink first).
4. Poll `/health` until ready or `LLAMACPP_START_TIMEOUT_MS`. Then read `/props` → served `n_ctx`. **That number feeds the budget** (L-M08), not the config value.
5. Port busy at start → fail closed with a clear message. No PID adoption, no `state.json`.
6. Stop: SIGTERM, wait, SIGKILL. On app exit, on error, on signal.

**Thread rule (CPU budget with the S2.4 embedder):**
`T = LLAMACPP_THREADS` if set, else `max(1, perfCores − EMBEDDING_THREADS)`.
`perfCores` = `sysctl hw.perflevel0.physicalcpu` on macOS (boot code, AP4 allows sync), else `os.availableParallelism()`. This machine: 8 − 2 = **6**. llama.cpp + embedder fill the P-cores; the E-cores keep the event loop. Measured cost of 6 vs 8: none for Ornith, inside the spread for gemma.

**Interface:**
- `startLlama(config) → { baseURL, servedCtx, capabilities, stop() }`
- `createChatProvider({ baseURL, tools, capabilities }) → { toolsJson, streamChat({ system, messages, emit, signal, thinking }) → result { text, toolCalls[], usage, timings, prefixHash, retries, error } }` (events go to `emit`)
- Events: `stream_start, token, reasoning_token, retract, tool_args_invalid, stream_end, error`.

**Errors:** binary missing · GGUF missing · port busy · start timeout · HTTP ≠ 200 · streamed error · idle stall → each one is an `error` event with the cause and is logged (AP5). Never an empty reply.

**Limits:** config (AP1): `LLAMACPP_SERVE_CTX` (cap) · `LLAMACPP_THREADS` (new, 0 = auto) · `LLAMACPP_START_TIMEOUT_MS` (new). Named constants, not tunables (only 2 new keys approved): stream idle 120 s · thinking 180 s · one retry each for empty / leak / echo / corrupt name. No module caches.

**Non-goals:** multi-step tool loop, repeat breaker, step cap (→ S2.8, see Q2) · router mode, VLM, other providers, model download, MTP / speculative decoding · history trim (→ budget function).

**Keeps / drops:** keeps the SSE reader, leak parsers, empty retry, header reader · drops router + preset + VLM + PID adoption (one model, one owned child), RAM-fit sizing (measured wrong), JSON repair (silent changes), system-prompt nudges and tool popping (prefix break).

## 4. Decisions (developer, 2026-11-11)

1. One step, not split.
2. The tool loop, repeat breaker and step cap go to S2.8. S2.5 parses one call and does the provider-level retries.
3. Config: add `LLAMACPP_THREADS` (0 = auto) and `LLAMACPP_START_TIMEOUT_MS`; drop `LLAMACPP_CTX` — the budget uses the served `n_ctx` (one number, not two that can disagree, L-M08).
4. No JSON repair. `bad_tool_json` is counted in the eval; repair returns only through the return gate.
5. Binary: `LLAMACPP_VENDOR_DIR` first, then `llama-server` on PATH.
6. Model missing → fail with a command. No download at start.
