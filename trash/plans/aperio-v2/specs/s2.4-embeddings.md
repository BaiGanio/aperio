## 1. v1 study (read at `archive/v1-final`)

**How v1 did it:** `lib/helpers/embeddings.js` (479 ln) picks a provider (transformers / Voyage / off) from env, keeps the signature `provider:model:dims`, and backfills at boot. `lib/helpers/embedding-worker.js` runs `mxbai-embed-large-v1` (`q8`, `cls` pooling, normalized) in a worker thread; query requests go before backfill requests. `lib/embeddings/reindex.js` (561 ln) is a state machine per store (`stale → reindexing → current`) with leases, heartbeats, a "cleared" checkpoint and settle rounds, for 5 vector stores.

**Best parts (keep):** one local model, cached on disk · worker thread, queries first · text = `title. content` · a failed row stays unembedded and is retried later · reindex is resumable at no cost.
**Bad parts (drop):** 3 providers and Voyage width tables (not core) · `process.env` read in the hot path (AP1) · module-level pipeline singleton (TR15) · the lease / checkpoint / settle machinery — it exists because v1 kept **one** signature per store. A signature **per row** (S2.3) makes "rows still to do" one query, so none of it is needed.
**Lessons:** L-C17 (signature per row, never mix vectors) · L-C15 (Buffer through a worker) · L-C16 (report max, not p95) · L-C07 (few deps) · L-C20 (no vectors → full-text still works) · L-P03 (no state frozen at import).
**v1 tests:** `tests/unit/helpers/embeddings.test.js` (688 ln) — **partly**: keep "pipeline gets text + pooling", "embed failure → null, logged", "backfill counts failed rows", "first run clears nothing", "model change flags rows". Drop all Voyage cases. `tests/integration/embeddings/reindex.test.js` (1 330 ln) — **partly**: keep "a killed reindex resumes and costs one call per row", "empty store completes", "provider returns nothing → rows stay for next run", "no vector support → zero embed calls". Drop leases, vec_meta, CLI, multi-store.

## 2. Spec (the contract)

**Goal:** turn text into vectors with one local model, and keep every stored vector in the current model's space.

**Behaviour:**
1. `createEmbedder({ model, cacheDir, log })` → `{ sig, dims, embed(text), embedQuery(text), close() }`. Config passes `EMBEDDING_MODEL` and `TRANSFORMERS_CACHE`. No module state.
2. **No network at run time:** `allowRemoteModels = false`. `npm run model:fetch` (`scripts/fetch-embedding-model.mjs`) is the only code that downloads.
3. `dims` = length of one probe embedding at load. `openStore({ dims })` uses it.
4. `sig` = `<model>|<dims>|q8-cls`. The last part names the code recipe (dtype + pooling); a recipe change in code changes it.
5. The model runs **in-process** (decision 1). Each memory is embedded once, when saved; a normal start embeds 0 rows.
6. `reindex(store, embedder, { signal })`: pages `listNeedingEmbedding(sig, 50)`, embeds `title. content`, calls `setEmbedding`. It stops when a page has no success (failed rows wait for the next run), or when `signal` aborts. Returns `{ done, failed }`. A model change is just rows with an old `sig`.
7. **Store change (S2.3 code, decision 2):** semantic search takes `sig` and uses only rows with that `sig`. This matters only after an `EMBEDDING_MODEL` change, while old rows wait for reindex: vectors from two embedding models must never mix (L-C17). On a normal day every row has the current `sig` and the filter changes nothing.
8. `scripts/try-search.mjs` loads the model, embeds the test memories, searches `auto`. No model → full-text, with one line that says so.

**Errors:** model not in cache → `EmbeddingUnavailable` that names `npm run model:fetch`; caller logs one warning and runs full-text only. Embed failure → logged, row counted `failed`, left for later. Never a silent `null` (AP5).
**Limits:** page 50. One embed blocks the event loop ~55 ms (max 98 ms measured). No cache of vectors (AP6). Config keys added: none.
**Non-goals:** other providers · worker thread (until measured need) · "edited while embedding" guard · embedding at insert time inside tools (S2.8) · minimum score (S2.6) · stop-word list · query prefix · batching.
**New dependency:** `@huggingface/transformers` 4.3.1 (v1 version).
**Files:** `src/embeddings/local-embedder.js` (`createEmbedder`, `EmbeddingUnavailable`; a leading `~` in `cacheDir` = home; optional `transformers` param = the module, a test hook) · `src/embeddings/embed-reindex.js` (`reindex(store, embedder, { signal, log })`) · `scripts/fetch-embedding-model.mjs` · store `search({ …, sig })`.
**Test change in S2.3:** `try:search` with a nonsense sentence no longer prints "no match" (meaning search always returns the nearest rows). The test now checks "no `fts` match". "No match" comes back with the S2.6 minimum score.

## 3. Acceptance (→ T2.4)

- [x] round-trip: embed → insert → semantic search finds itself at rank 1 (real model).
- [x] `sig` is stored per row; `dims` equals the vector length.
- [x] model change: rows with an old `sig` come back from `listNeedingEmbedding`; `reindex` fixes them; a second run does 0 calls.
- [x] resume (ported): abort mid-run, run again → one embed call per row in total.
- [x] embedder returns failure for one row → `failed: 1`, that row keeps `sig` NULL, the run ends.
- [x] mid-reindex search never uses an old-`sig` vector (teeth: remove the filter → red).
- [x] no network: a fetch stub that throws is never called; missing model → `EmbeddingUnavailable`.
- [x] `close()` frees the model; the process exits.
- [x] **eval number:** hybrid `hitRateAt5` ≥ 22/24, train and holdout apart; coffee query at rank 1.
- [x] tests that need the real model skip with a loud reason when it is not cached.

## 4. Decisions (developer, 2026-11-11)

1. **In-process, no worker.** Each memory is embedded once, at save. Re-embedding happens only after an `EMBEDDING_MODEL` change (rare). ~55 ms per turn is not noticeable. A worker comes back only on a measured need.
2. **Store change: the `sig` filter only.** One line in S2.3 search; S2.3 spec gets a matching note. The "edited while embedding" guard is dropped (a rare case inside a rare case).

## 5. Results (build, 2026-11-11)

- Hybrid `hitRateAt5`: **24/24** (train 16/16, holdout 8/8). Coffee query: rank 1, `fts+vec`.
- Teeth: with the `sig` filter removed, the mid-reindex test goes red.
- **Build finding:** the live model uses every CPU core. Run in parallel with the other test files, it pushed the S2.3 10k-row search test to max 41–49 ms (bar 25 ms). Alone: max 10 ms. So `npm test` now runs one file at a time (`--test-concurrency=1`): 8 s → 20 s. No test changed.
