**How v1 did it:**
- **At the tag, v1 has no auto-recall.** The deterministic recall ("Layer 2", `isRetrievalQuestion()` in `lib/agent/tool-profiles.js` ln 541–562) was cut on 2026-08-26 with the capability gates (`tests/integration/agent.test.js` ln 693). The regex is still exported, but nothing calls it.
- What is left: `lib/agent/preflight.js` ln 64–90 calls `recall({ type: "preference", limit: 8 })` every turn and appends the hits to `opts.extraSystem`, which is **the system prompt**. `getMemoryPointers()` (`lib/agent/index.js` ln 545) also puts session-memory text into the system prompt.

**Best parts (keep):** recall runs in code, every turn, not when the model chooses (L-M02) · "preview, not everything" framing (L-M01).

**Bad parts (drop / fix):**
- Recall goes into the system prompt, so the prefix changes on every turn. That is TR9 / L-M03, and on Ornith it costs all KV reuse (L-M22: 0.4 %, 24× slower).
- The intent regex is English-only and brittle (v1 needed a patch: "Remember that." matched as a question). In v2 a score threshold decides, not wording.
- No minimum score: semantic search always returns its nearest rows, even for "tell me a joke" (S2.3 carry).

**Lessons:** L-M01, L-M02 (code does the recall) · L-M03, L-M04, L-M22 (stable prefix) · L-M10 (tune on train only) · L-M11 (N = 5) · L-M18 (budget per turn, no preload) · TR9, TR14.

## 2. Spec (the contract)

**Goal:** before every turn, code finds the memories that matter for this message and puts them in the user turn, inside a token budget, without changing the stable prefix.

**Behaviour (`src/context/recall-block.js`, `src/context/assemble-turn.js`):**
1. Each turn, embed the user's text and search the store in **semantic** mode, top `RECALL_TOP_K`, filtered by the current embedding `sig`.
2. Keep only rows with cosine ≥ `RECALL_MIN_SCORE`. Semantic scores are absolute; hybrid scores are relative to the best row, so they cannot be gated.
3. Drop rows already injected earlier in this session. They are still in history, byte for byte.
4. No rows left → **nothing is injected**. No "no memories found" line.
5. Build the block best-first while it fits `RECALL_TOKEN_BUDGET`. A row that does not fit is skipped. If the first row alone does not fit, its content is clipped and marked `…`.
6. Token count = `ceil(chars / 3)`. This is an upper bound, and the live test checks it against llama-server `/tokenize` for both models. No tokenizer dependency.
7. The block goes **before** the user's text, in the **same user message**. The system message and tools are never touched (A2). The message is stored in history exactly as sent, so turn N+1 reuses turn N's KV cache.
8. Framing (L-M01): `Memories that may help (a preview, not everything stored):` then one line per row: `- [YYYY-MM-DD] Title: content`.
9. No embedder (model missing) → no block, a `recall_skipped` event with the reason, one `log.warn`. The turn still runs.

**Interface:**
- `buildRecallBlock({ store, embedder, text, session, config }) → { block: string | null, rows: [{ id, title, score }], tokens, ms }`
- `assembleUserTurn({ recallBlock, text }) → string`
- Session state: `session.injectedIds`, a `Set` that lives and dies with the session (cleared on `reset()`, freed on disconnect).
- Eval: a `v2-live` target adapter (`src/eval/`) wires store + embedder + S2.5 provider + this step. It fills `assembled = { toolsJson, system, userTurn }`. A config flag turns auto-recall off, for the baseline run.

**Errors:** embedder down → `recall_skipped`, logged (AP5) · store error → logged, rethrown: a broken store is not "no memories" · empty user text → no search.

**Limits:** `RECALL_TOP_K` (5) · `RECALL_TOKEN_BUDGET` (**800**: measured max block 607 tokens) · `RECALL_MIN_SCORE` (**new key**, whole percent, **50** = cosine 0.50; the registry has no float type). Recall step latency: max ≤ 100 ms at 1000 rows. No module caches (AP6).

**Non-goals:** the history trim and the full budget function (§4 Q3) · tools, and the multi-step loop (S2.8) · auto-capture (S2.7) · query rewriting or using earlier turns as the query · stop words · hybrid gating · the real system prompt (S2.6 uses a fixed 3-line test system).

**Keeps / drops:** keeps code-driven recall every turn and preview framing · drops the system-prompt injection (TR9), the English intent regex, and the 8-row preference preload.

## 3. Acceptance (becomes T2.6)

- [ ] zero relevant memories → nothing injected (off-topic prompt; empty store)
- [ ] 1000 memories that all match → block ≤ `RECALL_TOKEN_BUDGET`; one row bigger than the budget → clipped with `…`
- [ ] a row injected in turn 1 is not injected again in turn 2; `reset()` clears it
- [ ] stable prefix: over 3 turns with recall on, `toolsJson + system` is byte-identical and `prefixHash` is the same. **Teeth:** the block moved into `system` → red
- [ ] history keeps the injected user message byte for byte
- [ ] embedder missing → `recall_skipped` event + one warn, and the turn still answers
- [ ] new fixture `evals/off-topic.json` (12 prompts, 8 train / 4 holdout), reviewed by the developer
- [ ] **inject hit rate:** an expected title is in the block for ≥ 22/24 corpus queries, holdout ≥ 7/8, reported separately
- [ ] **off-topic inject rate** ≤ 1/12. **Teeth:** `RECALL_MIN_SCORE = 0` → red
- [ ] `ceil(chars/3)` ≥ real `/tokenize` count on every block, both models (live)
- [ ] **live, both models, N = 5:** `usedWithoutHint` on the seeded scenarios, recall **on vs off**. Bar: on ≥ 4/5 per scenario, and on > off
- [ ] live: KV on turns 2–3 with recall on: the **whole previous prompt is reused** (`cache_n` ≥ previous turn's prompt tokens). The % is reported, not gated (decision 6)
  - **Decision 9 (approved 2026-11-11):** split into (a) **client, exact:** the rendered prompt of turn N+1 (`/apply-template` + `/tokenize`) starts with every token of turn N's rendered prompt; (b) **server, loose:** `cache_n` ≥ previous prompt tokens − 8.
- [ ] recall step latency mean / sd / **max** at 30 and 1000 rows; max ≤ 100 ms

## 4. Decisions (approved 2026-11-11)

1. **Baseline.** S2.6 builds the `v2-live` adapter and runs recall **off** (the recorded baseline) and **on** (the result). The bar is on > off, plus the absolute bars in §3.
2. **`RECALL_MIN_SCORE`.** New tier-1 config key. Default set from the train split only.
3. **Budget function.** S2.6 builds only the recall part. The full function (history trim, A1 items 1–3) gets its own step before S2.8.
4. **Scenarios.** Add 2 seeded scenarios (1 train, 1 holdout), developer-reviewed.
5. **Fragile Zone.** S2.6 creates `src/context/`.
6. **KV bar.** The 97 % S2.5 bar does not fit an injected turn: the block is new text, so the % drops with a perfect cache (≈ 92 % by arithmetic). Bar: the whole previous prompt is reused. The % is reported (developer, 2026-11-11, option A).
7. **`RECALL_MIN_SCORE` = 50**, the §1 study value. The first build took the midpoint of the train gap (62); live, it dropped vague chat turns (SLO row 0.59, coffee row 0.53), because the corpus questions are clean and score ≥ 0.69. The test now checks that 50 fits the train split (developer, 2026-11-11).
8. **Coffee fixture.** "What should I get for Maya?" read as a gift question on gemma (2/5). Now "What coffee should I get for Maya?" — still no hint: the answer terms are not in it (developer, 2026-11-11).
9. **KV bar, split (developer, 2026-11-11, approved; gemma verified, Ornith later).** Live gemma run: `cache_n` was 5 short of the previous prompt (1834 vs 1839, run 0 turn 3). Diagnostic (2 × 2 runs, `/apply-template` + `/tokenize` on the exact request bodies): turn N+1's rendered prompt holds **all** of turn N's tokens, **0 mismatches** in 8 turn pairs. The shortfall is server-side: 0–5 tokens, varies run to run, also on a turn with no recall (turn 3) and on turn 2 after a fully cached turn 1 (1471 vs 1473). The server does not always keep the last few prompt tokens; it does not say why in its log. So decision 6 tests the server, not our prefix. New bar: (a) client, exact — every previous rendered token is a prefix of the next prompt; (b) server, loose — `cache_n` ≥ previous prompt − 8, which still catches a real break (a changed prefix costs hundreds of tokens).
