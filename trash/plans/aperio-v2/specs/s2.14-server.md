## 1. v1 study (read at `archive/v1-final`)

**How v1 did it:**
- `lib/server.js` (518 lines) → Express app, `helmet` CSP (`APERIO_CSP` on/report/off), static `public/`,
  ~20 API routes, listen on `HOST:PORT`, graceful shutdown.
- `lib/server/ws.js` (112) → `ws` `WebSocketServer` on the same HTTP server; `verifyClient` checks the
  `Origin` host against an allowlist (403) and an opt-in token (401); a 30 s ping sweep reaps dead sockets.
- `lib/emitters/handlers/wsHandler.js` (769) → one closure per socket holds history, `turnLock`, session id,
  logger, scratch dir. `ws.on('close')` aborts the turn. `ws/turnLock.js`: a new chat **supersedes** the old
  one (queue + identity guard; it needed its own bug hunt, T46).

**Best parts (keep):** origin allowlist (stops DNS rebinding from a web page) · ping sweep, `unref`'d
timer · close aborts the running turn · CSP on by default, no inline code (L-C11).

- AP8: `JSON.parse` + ad-hoc checks per case (fixed by S2.11; this step is the first caller).
- AP7: one 769-line closure; session state spread over ~15 `let`s, rebound by hand on resume.
- The supersede queue: real complexity for a case one person rarely hits.
- The turn wiring exists twice in v2 today if the server copies `src/eval/v2-live-adapter.js`.

**Lessons:** L-C11 (CSP) · L-C14/AP9 (no second `server.js`) · L-C16 (report max, not p95) · L-C28
(listeners in the same tick) · L-P02 (live runs isolated) · L-C25 (one `no-restricted-syntax` block per file).

## 2. Spec (the contract)

**Goal:** serve `public/` and one WebSocket; each socket gets one session object that runs chat turns
through the same code as the eval, and is freed on disconnect.

**Behaviour:**
1. **Turn runner** — `src/chat/turn-runner.js`: the per-turn code moves **out** of `v2-live-adapter.js`
   (recall → assemble → tool loop → `turn_complete`). The adapter and the server both call it. No copy.
2. **HTTP** — `src/server/http-app.js`: static `public/` and `GET /shared/ws-schema.js` (the same file,
   no build). Every response sets one CSP header: `default-src 'self'; connect-src 'self'; object-src 'none';
   base-uri 'none'; frame-ancestors 'none'`. No inline script or style is allowed by it.
3. **Socket edge** — `src/server/ws-edge.js`: `ws` with `maxPayload = WS_MAX_FRAME_BYTES`. Origin check
   (host must be `localhost`, `127.0.0.1`, `[::1]` or `HOST`; else 403, malformed 400). Every frame goes
   through `parseClientFrame` **once**; a bad frame → one `error` frame, the socket stays open. Every send
   goes through `encodeServerFrame`. Ping sweep 30 s, timer `unref`'d, cleared on close.
4. **Session** — `src/server/chat-session.js`: one object per socket: `{ id, history, recallSession,
   active: AbortController | null }`. All per-socket state lives here and nowhere else.
   - `chat` → runs one turn; every turn ends in exactly one `turn_complete`.
   - `stop` → aborts the active turn (`runToolLoop` gets `signal`, passed to `streamChat`) → `aborted`.
   - socket close → abort the turn, clear history, drop the session from the registry. Nothing kept.
5. **Boot** — `src/boot/start-server.js` + `npm start`: config → store (`SQLITE_PATH`) → embedder →
   llama → HTTP + WS on `HOST:PORT`. SIGINT/SIGTERM close in reverse order; a failed start closes what opened.

**Interface:** `createServer({ config, store, embedder, provider, system, tools, budget, log })` →
`{ listen(): Promise<{port}>, close(): Promise<void>, sessionCount(): number }`.

**Errors:** bad frame → `error{code}` (S2.11 codes) · busy → `error{code:'busy'}` + `turn_complete{status:'error'}`
· provider/tool error → `error` + `turn_complete{status:'error'}` · not-yet-wired type → `error{code:'not_ready'}`
· bad origin → HTTP 403 · frame > max → `ws` closes 1009 · a send to a closed socket is skipped and logged.

**Limits:** `WS_MAX_FRAME_BYTES` (exists) · `WS_MAX_CLIENTS` (new, default 4; extra → 503) · history is
bounded by the S2.13 budget · registry is a `boundedMap(WS_MAX_CLIENTS)` (AP6) · ping 30 s.

**Non-goals:** auth token, TLS, idle shutdown, sessions on disk, resume/branch, supersede queue, any UI,
memory messages (S3.4), settings routes (S3.6), `/api/*` routes.

**Keeps / drops:** keeps origin check, ping sweep, CSP-on · drops `helmet` (one header, no dep), the token,
the supersede queue, the 769-line closure.

## 3. Acceptance (becomes T2.14)

- [ ] runner: the adapter's recorded requests (tools, system, messages) are **byte-identical** before/after the move (fake fetch, 3 turns incl. a tool call and a trim)
- [ ] `GET /` and `GET /shared/ws-schema.js` → 200 + the CSP header; path traversal `/../package.json` → 404
- [ ] origin: allowed, none, other host 403, malformed 400, case-insensitive (ported from v1 `ws.test.js`)
- [ ] bad JSON / unknown type / extra field → one `error` frame, then a valid `chat` still works on the same socket
- [ ] chat (fake provider) → `stream_start … turn_complete` in order, exactly one `turn_complete`
- [ ] `stop` mid-turn → `turn_complete{status:'aborted'}`; a second `chat` while busy → `busy`
- [ ] close mid-turn → the provider sees `signal.aborted`; `sessionCount()` back to 0; no timer left (`node --test` exits)
- [ ] 5th client → 503 · ping sweep terminates a socket with no pong (ported)
- [ ] `close()` frees the port; a failed boot closes the store
- [ ] AP8 guard: in `src/server/**`, a `.send(` whose arg is not `encodeServerFrame(...)` fails lint (planted)
- [ ] live, once (scratch dir, port 3999, gemma, ~2 min): one chat through a real socket, answer streams, close frees the session
