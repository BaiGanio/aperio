## 2. Spec (the contract)

**Goal:** when the user explicitly asks to remember something, code saves it. Code captures nothing else.

**Behaviour:**
1. **When.** After `turn_complete`, off the reply path, one at a time per session.
2. **Input.** The user's text of that turn only.
3. **Trigger (code, no model call).** A sentence that **starts with** an explicit cue: `remember that` · `remember:` · `please remember` · `don't forget (that)` · `keep in mind (that)` · `save this:` · `note that`. Case-insensitive. The cue list is one module with tests.
4. **Not a trigger:** a question ("Do you remember my dentist?", "Remember when we fixed it?") · "remember" in the middle of a sentence ("I can't remember the port") · any statement with no cue ("Heads-up: the standup moves to Thursday").
5. **What is saved:** the sentence with the cue removed ("Remember that my dentist is Dr. Ivanova." → "My dentist is Dr. Ivanova."). `title` = first 8 words, `type` = `fact`, `source` = `capture`, with its vector and signature.
6. **Pointer-only ask is not saved by code:** if fewer than 3 words remain, or the rest is only `that` / `this` / `it` / `what I said` ("Remember that.", "Remember this!"), code cannot know what "that" is. It emits `capture_unresolved` (§4 Q2 decides who handles it).
7. **Secret check:** a sentence that matches a secret pattern (`sk-…`, `ghp_…`, `AKIA…`, a PEM header, `password:`/`token:` with a value, a hex/base64 run ≥ 32 chars) is **not saved** and not logged. Code emits `capture_secret_refused`, so the UI can say "Not saved: this looks like a secret."
8. **Duplicate check:** a stored memory scores ≥ `CAPTURE_DUP_SCORE` → no new row; `capture_duplicate` is emitted.

**How capture stays out of the stable prefix** (the one rule: code does the memory work, the model only talks):
- **No model call.** llama-server has one slot; a side prompt would overwrite its KV cache (L-M22: next turn 0.35 s → 8.2 s on Ornith).
- Capture writes only to `memories`. It never edits the system prompt or the tool array, and adds no tool.
- A saved memory reaches the model only through the S2.6 recall block, in a **later** user turn.
- Test: 3 turns, capture fires on turn 1 → `stablePrefix` byte-identical on all turns; the S2.6 client-token-prefix check holds.

**Interface:**
- `src/capture/capture-cues.js` → `findExplicit(text) → [{ sentence, content } | { sentence, unresolved: true }]` (pure).
- `src/capture/secret-scan.js` → `hasSecret(text) → boolean` (pure).
- `src/capture/capture-turn.js` → `captureTurn({ text, store, embedder, config, emit, log }) → { saved, duplicate, unresolved, secretRefused }`.
- Event `capture_done` with those counts plus the saved ids. **No text in events or logs.**

**Errors:** embedder unavailable → save without the vector (the S2.4 reindex fills it later), skip the duplicate check, one `warn` per session · store error → log `error`, emit `capture_failed`, the chat goes on (AP5).

**Limits (config, AP1):** `CAPTURE_MODE` `on|off` (default `on`) · `CAPTURE_DUP_SCORE` 85 (measured on the fixture before it is fixed) · `CAPTURE_MAX_PER_TURN` 3. Step max ≤ 100 ms at 1 000 memories.

**Non-goals:** catching facts without a cue · reading assistant text · an inbox or approval flow · languages other than English (a Bulgarian cue list comes through the return gate) · model-based extraction · updating an existing memory ("Remember that the standup is now Friday" adds a row; it does not edit the old one).

**Keeps / drops from v1:** keeps "save and move on" for explicit asks. Drops `propose_memory` and the inbox (developer scope cut), and the model-dependent trigger (L-M02).

**Fixture change (needs your OK with the spec):** the two cross-session scenarios get explicit wording in session A: pager "For the record: …" → "Remember that …"; standup "Heads-up: …" → "Remember that …". A copy of the old "Heads-up" wording goes into the offline fixture as a **skip** case.

## 3. Acceptance (becomes the tests)

- [ ] "Remember that my dentist is Dr. Ivanova." → 1 memory "My dentist is Dr. Ivanova.", with a vector; semantic search finds it.
- [ ] "Do you remember my dentist?" / "I can't remember the port." / "Heads-up: the standup moves." → 0 rows.
- [ ] "Remember that." → 0 rows, `capture_unresolved`.
- [ ] "Remember my key is sk-…" → 0 rows, `capture_secret_refused`, no text in logs.
- [ ] the same ask twice → 1 row, `capture_duplicate`.
- [ ] `CAPTURE_MODE=off` → 0 rows for any text.
- [ ] embedder down → row saved without a vector, one `warn`.
- [ ] stable prefix: 3 turns, capture on turn 1 → prefix bytes identical; client token prefix check passes.
- [ ] **Capture eval, offline (CI, deterministic):** `evals/capture.json`, turns labelled `save` (with required terms) or `skip`, split train / holdout. Bars: save hit **train 20/20, holdout 10/10** (cue rules are exact, so a miss is a bug) · false saves **0/24** skip turns · secrets saved **0** · step **max ≤ 100 ms** at 1 000 rows (N = 5, mean / sd / max).
- [ ] **Capture eval, live (gemma, N = 5):** the 2 cross-session scenarios, empty store, capture on. Bar: usedWithoutHint **≥ 4/5 each** on, **0/5** off. Ornith: the developer runs it.
