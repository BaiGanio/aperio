## 1. v1 study (read at `archive/v1-final`)

**How v1 did it** — v1 had *two* evaluators and neither one measured memory quality end to end.

- `tests/harness/run-scenario.js` (95 ln) → `runScenario(t, scenario)` — mkdtemp sandbox, MCP stubbed at the SDK layer, host tools faked, **real** `runAgentLoop` + middleware + path gate, events captured by `makeSinkEmitter()`, driver emits `turn_complete` itself.
- `tests/harness/mock-provider.js` (111 ln) → `runMockLoop()` — replays a flat `providerScript` of `{tool}` / `{text}` / `{plan}` turns; `$lastArtifactId` substitution; refuses to resolve outside `NODE_ENV=test`.
- `lib/helpers/modelTierBench.js` → `evaluateBenchmarkCase(caseDef, events)` — the one shared scorer: ordered-subsequence tool match, required answer terms, all-tools-ok, `turn_complete{completed}`, argument assertions.
- `scripts/model-tier-bench.js` (645 ln) → live 65-drill exam against a real model. Manual, minutes, nondeterministic.
- `lib/memory/compactionBaseline.js` → `hitRateAtK(store, queries, k, mode)` over `tests/fixtures/memory-compaction/recall-corpus.json` (16 queries) against `.github/capability-exam/exam.memories.json` (28 memories).

**Best parts (keep):**
- Real loop, fake model. Only the model turn is scripted; every guardrail is the production one.
- **One scorer, one scenario JSON shape** shared by the deterministic and the live evaluator, so a case can move between them.
- Per-run `mkdtemp` sandbox torn down in `t.after()` — no stray state.
- Scenario titles written as plain sentences, because they double as dashboard row labels.
- "Prove it has teeth": every check must be shown to go red against a deliberate break.
- A ready-made recall corpus with `expectedTitles`, and a corpus **self-test** (`recall-corpus.test.js`) that catches fixture bugs (a query phrased as filter prose scores a meaningless 0%).

**Bad parts (drop / fix):**
- **One `runAgentLoop` call per scenario.** Multi-turn coverage was exactly **zero** — trim, orphaned `tool_result`, tail slicing, cross-turn guardrail state and the stable prefix had no test (A1).
- The stable prefix was checked by a **live benchmark someone had to remember to run** (`prompt-cache-bench.js`), not by CI (A1 item 4, L-M03/M04).
- **No scores at all** in the deterministic layer: pass/fail only. No recall number, no "used without hint" number.
- Live exam: **one run per case**, no seed, no spread (TR11/L-M11); latency reported as a single `durationMs` per turn — **no max, no p95, no event-loop lag** (TR12/L-C16); no holdout set (TR10/L-M10).
- Two confirm lists (`CONFIRM_TOOLS` vs `CONFIRMABLE_TOOLS`) that nothing asserts agree — a v1 debt note.
- AP-adjacent: the live bench reads config from env directly (AP1) and does sync `fs` on its run path (AP4).

**Lessons that apply:** L-M10 (holdout, train 0.73 / holdout 0.5), L-M11 (N≥5, seed, mean+spread), L-C16 (max + event-loop lag, not p95), L-M14 (port the false "no tool use" regression), L-M16 (allowlist leak invalidates a run — isolate), L-M19 (**grade deterministically, never by model judgement**; say which rung a pass means), L-M03/M04 (recall after the stable prefix), L-P02/L-P03 (throwaway workdir; set env **before** dynamic import).

## 2. Spec (the contract)

**Goal:** one fixture set, one runner and one deterministic scorer that measure memory behaviour over multiple turns, and a recorded v1 baseline for both local models that v2 must match or beat.

**Shape — one runner, swappable targets.** v2 has no store, provider or loop yet, so the runner never imports v2 internals. It talks to a **target adapter**:

```
TargetAdapter = {
  name: string,                      // "v1-live" | "mock" | "v2-live"
  start(opts): Promise<Session>,     // isolated: own workdir, scratch DB, non-default port
  stop(): Promise<void>,
}
Session = {
  seedMemories(rows): Promise<void>,
  recall(query, k): Promise<{ titles: string[] }>,
  turn(text): Promise<{ events: object[], text: string, assembled?: Assembled }>,
  reset(): Promise<void>,            // new session, SAME store (cross-session recall)
}
Assembled = { toolsJson: string, system: string, userTurn: string }  // mock/v2-live only
```

S2.1 ships `v1-live` only. `mock` lands with the v2 loop (S2.5/S2.6) and `v2-live` after it; the fixtures, scorer and metrics do not change when they do.

**Fixtures** (`evals/`):
1. `memories.json` — ~30 rows: v1's 28 `exam.memories.json` rows, **re-dated** across the last 8 weeks (relative dates resolved to absolute at seed time from a fixed `asOf`), plus 2 new rows that exist only to be set in one session and used in another.
2. `corpus.json` — v1's 16 recall queries, each tagged `split: "train" | "holdout"` (10 / 6).
3. `scenarios/*.json` — multi-turn cases, each tagged `split`. Minimum set: 3 `used-without-hint`, 2 tool-call, 1 trim-under-pressure, 1 tail-slice, 1 cross-turn-guardrail, 1 empty-completion quirk.

**Scenario contract** (settles #357):

| Term | Meaning |
|---|---|
| scenario | `{ id, title, split, sessions[] }` — one store, seeded once from `memories.json` |
| session | `{ id, turns[] }` — one persistent agent and one persistent history; a new session keeps the store and drops the history |
| turn | `{ user, providerScript?, expect{} }` — `providerScript` is used only by the `mock` adapter and ignored by live ones |
| event slice | the events between this turn's first `stream_start` and its `turn_complete` |
| `turn_complete` | emitted once per turn, `status: "completed" \| "interrupted"` |
| turn-local control | abort and pending-confirm end **their own** turn; later turns in the session still run |

**Metrics** (4, per model, deterministic — no model judge, L-M19):

| Metric | Definition |
|---|---|
| `hitRateAt5` | share of corpus queries where any `expectedTitles` entry is in the top 5 recall rows. Reported per mode (semantic / fulltext / auto) and per split |
| `usedWithoutHint` | share of `used-without-hint` turns whose answer contains every `requiredAnswerTerms` entry, with no recall tool named by the user |
| `toolSuccess` | share of tool-call turns passing ordered-subsequence tool match **and** required terms **and** all-tools-ok **and** `turn_complete{completed}` (v1's scoring rules, rewritten) |
| `latency` | per turn: mean · stdev · p95 · **max** · **max event-loop lag** (L-C16/TR12) |

**Runs:** every case `N = 5` (configurable), temperature 0 and a fixed seed where the provider accepts one. Report mean and spread; a single run is never a result (L-M11). Train and holdout are reported **separately, always** (L-M10).

**Stable prefix** (settles #356, declared here, asserted when an `assembled`-capable adapter exists): the runner records `Assembled` per turn. The **stable prefix is `toolsJson` + `system`** — compared byte for byte across turns 2..N of a session. Deliberately turn-varying: the recall block and the user text, both inside `userTurn`. Protected invariant: llama.cpp KV prefix reuse (one tool added or removed → 0% hit, A2). Teeth: moving the recall block into `system` must make it fail.

**Fixture arithmetic** (settles #358): the trim case sets the context window to an explicit small value from config and sizes history to exceed it by a known margin, so the expected `dropped` count is **computed, not guessed**, and lands inside the branch, not on its boundary. The tail-slice case keeps total tokens under the window so only the `maxHistory` branch runs. Deterministic layer: ≤ 2 s total. Every check must be shown red against a named deliberate break.

**Errors:** a target that will not start, a missing fixture title, or a corpus query with no `expectedTitles` fails loudly with the id. An empty completion (gemma quirk) is retried up to 2× and counted as `emptyRetry`, never silently. Nothing is swallowed (AP5).

**Limits:** every tunable (`N`, `k`, context window, timeouts, model paths, port) comes from config (AP1); no module-level const (TR15, L-P03). Event arrays are bounded per turn and dropped after scoring (AP6). Each run gets its own workdir, scratch DB, non-default port and its own allowed-paths list (L-M16, L-P02), torn down on success **and** failure.

**Non-goals:** no model-graded scoring · no port of the 65-drill tier exam (`never`) · no live run in CI (`eval:live` is manual; only the fixture self-test and, later, the deterministic layer are in `npm run check`) · no skill on/off measurement (S2.10) · no autotune loop · no UI or dashboard · no Postgres · no v1 DB import (S2.12) · no tuning of anything against these numbers in this step.

**Keeps from v1:** the real-loop/fake-model design · the shared scorer's rules · one scenario JSON shape across evaluators · the mkdtemp sandbox · the recall corpus and its self-test · plain-sentence titles · the teeth drill.
**Drops from v1:** single-turn-only driving (A1) · single-run, unseeded scoring (TR11) · p95-only latency (TR12) · live-benchmark-as-prefix-check (A1 item 4) · the tier-exam runner and every `never`-feature scenario.

## 3. Acceptance (becomes T2.1)

- [ ] ported v1 test: `tests/unit/memory/recall-corpus.test.js` → fixture self-test over `evals/` — every `expectedTitles` exists verbatim in `memories.json`; ≥6 semantic and ≥6 keyword; no filter-prose keyword query; every query has ≥1 expected title; **every fixture has a `split`**
- [ ] `memories.json` has ~30 rows with absolute dates spread over 8 weeks, derived from one fixed `asOf`
- [ ] scenario-schema test: every scenario has `id`, `title`, `split`, ≥1 session, ≥2 turns total; one scenario has ≥2 sessions over one store
- [ ] adapter-contract test: a fake adapter satisfies the full `TargetAdapter` / `Session` shape; a missing method fails with its name
- [ ] isolation test: a run creates its workdir, scratch DB and port under one temp root, and **nothing remains** after success *and* after a thrown failure
- [ ] metric unit tests on hand-built event arrays: `hitRateAt5`, `usedWithoutHint`, `toolSuccess`, and latency returning mean · stdev · p95 · max · max event-loop lag
- [ ] `toolSuccess` fails a deliberately wrong `expectedToolSequence` (v1's teeth check, kept)
- [ ] train and holdout are reported as separate numbers; a run that scores only one of them fails
- [ ] `N = 5` by default, from config; the report carries mean **and** spread; `N = 1` is rejected unless explicitly forced
- [ ] an empty completion is retried and counted as `emptyRetry`
- [ ] `eval:live` against **v1 at the tag** (throwaway worktree, scratch DB, non-default port) writes `evals/baseline.json`: all 4 metrics, per model, per split, with `N`, seed, model ids, commit and date
- [ ] teeth drill written down and run: one named deliberate break per metric makes its check go red

## 4. Open questions (answer before approval)

1. **How the v1 baseline is driven.** (a) **black box** — boot v1 in a throwaway worktree at the tag, scratch DB, non-default port, talk over its WebSocket; or (b) import v1 modules directly into the runner. **I would take (a)**: it keeps v1 code out of v2 ("pull, don't push"), survives v1's internals, and exercises the same path a user does. Cost: a full `npm install` of v1 in that worktree, including native `sqlite-vec` and the local embedding model — minutes, and it must live outside both repo trees.
2. **The two models.** Confirm `gemma-4-E4B-it-qat` and `Ornith-1.0-9B-MTP`, and that the harness may read the existing `var/models/` directory read-only rather than re-downloading.
3. **Naming.** T2.1 says "recall precision@5". What v1 measures, and what this spec defines, is **hit-rate@5** (any expected title in top k). Precision@5 would be a different, stricter number. OK to record it as `hitRateAt5` and correct T2.1's wording?
4. **One step or two.** The harness and the baseline run are one plan step but two very different costs. I would keep one step, in two commits: `feat(eval): fixtures, runner, metrics` then `chore(eval): record v1 baseline`. Say if you want them as S2.1a / S2.1b instead.
5. **Holdout split.** 10 train / 6 holdout on a 16-query corpus is thin. Accept it as-is for the baseline, or author ~8 more queries first so the split is 16/8?
