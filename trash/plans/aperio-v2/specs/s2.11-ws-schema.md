## 1. v1 study (read at `archive/v1-final`)

**How v1 did it:**
- `lib/server/ws.js` (`ws` package): origin + auth check in `verifyClient`; `maxPayload` derived from the
  attachment budget (before that: the `ws` 100 MiB default killed the socket, no refusal).
- `lib/emitters/handlers/wsHandler.js` (769 lines) → `JSON.parse(raw)` then `switch (data.type)` with
  **18** client types (`init`, `chat`, `stop`, `get_memories`, `delete_memory`, `handoff`, `switch_model` …).
  Each `case` checks its own fields ad hoc (`typeof data.lang === "string" && data.lang.length <= 8`).
- The server sent **28** types through `send("<type>", payload)`; the client had its own string list.

**Best parts (keep):**
- One error path: a handler error → `error` frame + `turn_complete{turnId, status:'error'}` (the UI never hangs).
- `turnId` from the client, bounded (≤ 128 chars); every turn ends in exactly one `turn_complete`.
- Malformed JSON → an `error` frame, the socket stays open (v1 test "sends error event when message is not valid JSON").
- A frame-size cap that is a decision, not a library default.

**Bad parts (drop / fix):**
- **AP8:** no schema. Field checks are spread over 18 cases; some bad input is **silently ignored**
  (`set_paths` "is silently ignored when paths is not an array" — that was a v1 *test*). **No `default:`
  case:** an unknown type did nothing, with no error.
- Client and server kept separate type lists; a renamed type broke silently.
- **AP7:** the handler grew to 769 lines; parsing, checking and work lived in one closure.
- 15 of the 18 types are not v2 core (self-memory, handoff, roundtable, discuss, suggestions, model switch …).

**Lessons that apply:** AP5 (no silent ignore) · AP7 · AP8 · L-C28 (attach listeners in the same tick).
No ledger lesson is about the socket itself; v1's 769-line handler is the lesson.

**v1 tests found:**
| Test file | What it covers | Reuse? |
|---|---|---|
| `tests/unit/handlers/wsHandler.test.js` (1217 lines) | per-type handler behaviour; "not valid JSON → error event" | **partly** — the malformed-JSON case; the rest tests handlers, not a schema (S3.x) |
| `tests/integration/server/ws.test.js`, `tests/e2e/websocket/*` | origin, auth, ping sweep, streaming | **no** — no server in this step (S3.0) |

**v1 numbers:** nothing to measure. Count only: 18 client types, 0 shared schema, 0 unknown-type errors.

## 2. Spec (the contract)

**Goal:** one module lists every socket message and its fields; one call checks a frame at the edge.

**Behaviour:**
1. `src/shared/ws-schema.js` is pure ESM: no `node:` imports, no deps, no state. The browser imports the
   same file later (S3.0, served as a plain file, no build).
2. Every message is `{ type, ...fields }`. Each type lists its fields: kind (`string` / `int` / `bool` /
   `object` / `array`), required or optional, and a max length for strings and arrays.
3. **Client → server (5 types):** `chat {turnId, text}` · `stop {turnId?}` · `memories_list {}` ·
   `memory_update {id, content}` · `memory_delete {id}` (the memory table, S3.4 — see §4.3).
4. **Server → client:** the events the turn already emits — `stream_start`, `token`, `reasoning_token`,
   `tool_start`, `tool_result`, `tool_args_invalid`, `retract`, `stream_end`, `recall_injected`,
   `recall_skipped`, `turn_complete`, `error` — plus `memories {rows}`. Every server frame carries `turnId`
   when it belongs to a turn.
5. The server calls `parseClientFrame(raw)` **once**, before its switch. The switch never sees an
   unchecked message. A bad frame → one `error` frame back; the socket stays open.
6. The server builds frames only with `encodeServerFrame(msg)`. An unknown type or a bad field there is
   a **bug**: it throws (in tests and in dev), never sends a half-valid frame.

**Interface:**
```js
CLIENT_TYPES, SERVER_TYPES                       // frozen { type: { field: spec } }
parseClientFrame(raw: string | Buffer) →
  { ok: true, msg } | { ok: false, error: { code, message, type? } }
encodeServerFrame(msg) → string                  // JSON; throws on unknown type / bad field
```
`code` ∈ `bad_json` · `too_large` · `not_object` · `unknown_type` · `bad_field` · `missing_field` · `extra_field`.

**Errors:** every reject returns a code and a plain message naming the field (`chat.text: must be a
string`). Nothing is dropped silently (AP5). The raw frame is **never** echoed back (it may hold a secret).

**Limits:** frame ≤ `WS_MAX_FRAME_BYTES` (checked before `JSON.parse`), `turnId` ≤ 128 chars, `text` ≤ frame
size, arrays bounded. Value and config place: §4.4.

**Non-goals:** no socket server, no `ws` dependency, no auth / origin check, no ping sweep (all S3.0) · no
handlers · no UI · no attachments, sessions, model switch, self-memory, handoff (not core).

**Keeps from v1:** bounded `turnId`, one `turn_complete` per turn, error frame on bad JSON, a decided size
cap. **Drops:** ad hoc checks per case, silent ignore, separate client/server lists, 13 non-core types.

## 3. Acceptance (becomes T2.11)

- [ ] every client type: a valid sample → `ok`; each required field missing → `missing_field`;
      each field with a wrong kind → `bad_field`; a string over its max → `bad_field`.
- [ ] unknown type, missing `type`, `type` not a string → `unknown_type` / `not_object`.
- [ ] not JSON, JSON array, JSON `null`, a number → `bad_json` / `not_object`; never throws.
- [ ] a frame over `WS_MAX_FRAME_BYTES` → `too_large`, and `JSON.parse` is not called.
- [ ] prototype keys (`__proto__`, `constructor`) in a frame do not reach `msg`'s prototype.
- [ ] the error never contains the raw frame text.
- [ ] `encodeServerFrame`: every server type round-trips; unknown type or bad field throws.
- [ ] every event type emitted in `src/` (`emit({ type: … })`) has a `SERVER_TYPES` entry (static contract test).
- [ ] the schema file imports nothing from `node:` (browser-safe).
- [ ] reused v1 case: "not valid JSON → error, socket stays open" (as `bad_json`, no socket).

## 4. Open questions (developer decides)

1. **Validator:** **A — hand-written, ~100 lines, no dependency (my pick).** 5 + 13 flat types do not need
   a library. **B — a library** (`ajv` / `zod`): more power, a new dependency in browser and server.
2. **Extra fields in a client frame:** **reject with `extra_field` (my pick)** — a typo shows up at once.
   Or **ignore** them — older clients keep working after a field is removed.
3. **Memory table over the socket:** **yes (my pick)** — `memories_list` / `memory_update` /
   `memory_delete`, one channel, one schema. Or **HTTP** routes in S3.4 — then the socket has only `chat` + `stop`.
   Either way the user does it, not code (the one rule holds).
4. **Frame cap:** a new config key `WS_MAX_FRAME_BYTES`, default **256 KiB (my pick)** — touches
   `src/config/` (Fragile Zone). Or a fixed constant in the schema with a `// why` line.
