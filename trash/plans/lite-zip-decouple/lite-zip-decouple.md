# Lite zip decoupling

## Objective

Shrink the `aperio-lite-vX.Y.Z.zip` release artifact to the minimum the SQLite-only lite
app actually needs at runtime, by (1) fixing a stale, duplicated CI exclude list and (2)
removing the Postgres backend's *unconditional* load-bearing status so its files — the
biggest remaining excludable chunk — can finally be dropped from the zip too.

## Background (audit findings)

- `ZIP_EXCLUDES` in `.github/workflows/cd.release.yml` is dead: defined as an env var but
  never referenced — the actual `zip -r ... -x ...` step hardcodes its own separate list
  that has drifted from it.
- Several current excludes target paths that no longer exist in the tracked tree
  (`.lancedb/*`, `lite/*`, `deno.json`, `deno.lock`, `dist/*`, `launchers/*`,
  `release_summary.txt`, `lite-progress.md`).
- New tracked top-level dirs were never added: `audit/`, `vms/`, `k8s/`, `scripts/`,
  `integrations/`, `trash/` — all dev/CI-only, confirmed via grep that nothing in the
  runtime import graph reads them.
- `id/` is *partially* load-bearing (`lib/agent/index.js` reads `id/whoami.md`,
  `id/whoami-<persona>.md`, `id/capabilities.md`, `id/self-nature.md`,
  `id/characters/*.md` for system-prompt assembly) — `id/reference/*`, `id/audit/*`,
  `id/agent-rules/*`, `id/capability-tiers.md` are not read anywhere and are safe to drop.
- `db/` is almost entirely runtime-required (`db/index.js` → `db/sqlite/store.js`
  statically imports `memory-seed.js`, `memory-seed-lite.js`, `wiki-seed.js`,
  `self-memory-seed.js`, `agent-job-seed.js`, `encrypt.js`, `migrate-sqlite.js`) — only
  `db/migrate.js` (Postgres-only CLI script, unimported) and `db/migrations/*`
  (Postgres SQL, already excluded) are dead weight *before* this plan's Postgres work.
- `.env.example` is 100% auto-generated by `scripts/gen-env-example.js` from
  `lib/config.js`'s `CONFIG` registry; `gen:env:check` fails CI on any hand-added line
  that doesn't round-trip through the registry, and the registry's contract is
  "every variable Aperio reads at runtime" — `ZIP_EXCLUDES` is neither, so it cannot live
  there. It also isn't something lite users ever touch (`APERIO_LITE=on` forces
  `APERIO_CONFIG_PRECEDENCE=db`; the UI is authoritative) — good reason to exclude the
  *file* from the shipped zip, separate from where the CI exclude list itself should live.
- `db/postgres.js` (and by barrel re-export, `db/postgres/store.js`, which does
  `import pg from 'pg'`) is currently **unconditionally** imported by three always-loaded
  modules, not just the Postgres backend path:
  - `db/index.js:10` — static `import { PostgresStore } from './postgres.js'`
  - `lib/handlers/memory/memoryHandlers.js:3` — `import { localeToPgConfig } from "../../../db/postgres.js"`
  - `lib/handlers/memory/selfMemoryHandlers.js:3` — same
  The two handler files are core memory code, loaded in every mode including lite. Because
  Node ESM resolves imports before any code runs, removing `db/postgres.js`/`db/postgres/*`
  from the zip today would crash `node server.js` at boot in SQLite mode too
  (`ERR_MODULE_NOT_FOUND`) — this is a code fix, not a zip-config change.

## Model recommendation

Mostly mechanical edits (two import-path swaps, one static→dynamic import conversion, a
new text file, a YAML rewrite) — a local llama.cpp pass or DeepSeek is sufficient for the
edits themselves. Reserve a Sonnet-tier pass for the verification steps (5 and 6 below):
`db/index.js` sits in the module coupling map and a mistake there fails silently (wrong
error surfaces through the existing try/catch fallback-to-SQLite in `getStore()`, masking
a real regression as "Postgres unavailable"). Estimated: ~15K input / ~3K output tokens
for the full pass including the boot smoke test transcript; negligible cost either way.

## Steps

1. **Redirect memory handlers off the Postgres barrel.** In
   `lib/handlers/memory/memoryHandlers.js` and `lib/handlers/memory/selfMemoryHandlers.js`,
   change the import to pull `localeToPgConfig` from `db/postgres/mappers.js` directly
   (pure module — only imports `../types.js`, no `pg`).
   *Works when:* `grep -rn "from ['\"].*db/postgres\.js['\"]" lib/` returns no hits, and
   `grep -rn "from ['\"].*db/postgres/mappers\.js['\"]" lib/handlers/memory/` returns both
   files. See test group **T1** in the companion test file.

2. **Make `db/index.js`'s Postgres import lazy.** Replace the top-level
   `import { PostgresStore } from './postgres.js'` with a dynamic
   `const { PostgresStore } = await import('./postgres.js')` inside `initBackend()`'s
   `backend === 'postgres'` branch only.
   *Works when:* `db/index.js` has no static top-level import of `./postgres.js`; SQLite
   boot path never touches the module. See **T2**.

3. **Confirm no other always-loaded module statically imports Postgres files.**
   Repo-wide grep for `from ['"].*db/postgres` outside `db/index.js`. The one other hit
   (`lib/db-connect/registry.js`, a separate `db_connect` tool feature) must be confirmed
   reached only via an explicit tool call, never at boot — leave it as-is, it's out of
   scope (see Risks).
   *Works when:* grep hits are limited to `db/index.js` (now dynamic) and
   `lib/db-connect/registry.js` (confirmed lazy/tool-gated). See **T3**.

4. **Create `.github/zip-excludes.txt`** — one glob per line, the single source of truth
   for the release zip's exclude list (per the elenchus above, this replaces the earlier
   idea of putting it in `.env.example`, which the generator contract rules out). Content:
   git/node_modules/CI dirs, dev-only top-level dirs (`audit/`, `vms/`, `k8s/`, `scripts/`,
   `integrations/`, `trash/`), dev-facing root docs (`CONTRIBUTING.md`, `CHANGELOG.md`,
   `FEATURES.md`, `AGENTS.md`, `.env.example`, `.dockerignore`, `.gitignore`), the
   already-excluded Postgres-only DB pieces (`db/migrations/*`, `db/migrate.js`, and now
   `db/postgres.js` + `db/postgres/*`), and the dead-and-gone stale entries dropped.
   *Works when:* file exists, one pattern per line, no stale entries. See **T4**.

5. **Wire `cd.release.yml` to the new file; delete the dead `ZIP_EXCLUDES` env var.**
   Replace the hardcoded `-x` list in the `Build ZIP` step with
   `zip -r "$ZIP_NAME" . -x@.github/zip-excludes.txt` (verify `zip`'s `-x@` syntax against
   the version on `ubuntu-latest` — see Risks).
   *Works when:* no hardcoded duplicate list remains in the YAML; the workflow still
   produces a valid zip. See **T5**.

6. **Boot smoke test from a clean extracted zip.** In an isolated scratch dir: build the
   zip from a clean tag checkout, extract it, physically confirm `db/postgres.js` is
   absent, run `npm install && npm run start:lite`, and exercise a memory save/recall
   round-trip through the API. Tear down after (no stray state left in the repo tree, per
   the standing no-side-effect-processes rule).
   *Works when:* the app boots with no `ERR_MODULE_NOT_FOUND`/Postgres-related error, and
   the recall round-trip succeeds. See **T6**.

7. **Postgres regression check.** With the files present (i.e., running against the
   full repo, not the trimmed zip), force `DB_BACKEND=postgres` against a real or
   docker-composed Postgres and confirm the dynamic import still resolves and the store
   initializes normally — the refactor must not regress the non-lite path.
   *Works when:* existing Postgres integration/contract tests pass unchanged. See **T7**.

## Risks

| Risk | Mitigation |
|---|---|
| Dynamic import failure inside `initBackend('postgres')` surfaces as a different error than before (e.g. "module not found" vs. "connection refused"), confusing ops/users who explicitly set `DB_BACKEND=postgres` | `getStore()` already wraps the postgres init call in try/catch with fallback to SQLite — confirm the error message logged by `logError` still distinguishes "Postgres files missing" (should never happen outside the lite zip) from "Postgres unreachable" |
| `createVectorStore()` (`db/index.js:117-119`) calls `initBackend(resolveBackend())` **without** a try/catch, unlike `getStore()` — a dynamic import failure here throws uncaught | Verify at implementation time whether this is reachable with `backend === 'postgres'` in a lite-zip context (it shouldn't be, since lite hardcodes `DB_BACKEND=sqlite`) but note the asymmetry with `getStore()`'s guarded path regardless |
| Missed static importer of `db/postgres.js` elsewhere in the graph (grep is a snapshot, not a guarantee) | Step 6's boot smoke test with the files *physically absent* is the real proof — stronger than any grep pass |
| `zip -x@file` pattern-file syntax may behave differently across `zip` versions/platforms (macOS dev machine vs. `ubuntu-latest` runner) | Test the exact CI runner image, not just locally; keep `unzip -l` verification step in the workflow |
| `pg` remains a `dependencies` (not `devDependencies`) entry in `package.json`, so `npm install` in the extracted lite zip still installs it even after `db/postgres.js` is excluded from the zip contents | Out of scope for this plan — flag as a follow-up (package.json dependency splitting for lite) in `A2D.md` |
